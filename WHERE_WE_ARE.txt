1. BIG PICTURE
---------------------------------------------------
Smart School System is a full school-management platform:
  - Express.js + PostgreSQL backend  (REST API, JWT auth)
  - Next.js 15 / React 19 frontend   (role-based dashboards)
  - Local dev DB: Postgres 15 via docker-compose on port 5433
  - 11 user roles (SUPER_ADMIN, ADMIN, PRINCIPAL, VP_ACADEMIC,
    VP_ADMINISTRATION, DEPARTMENT_HEAD, TEACHER, STUDENT, PARENT,
    PTSA_REPRESENTATIVE, SIC_MEMBER)
  - ~105 frontend page routes across 10 role dashboards
  - 12 database migrations

3. WHERE WE ARE IN THE PROJECT
---------------------------------------------------
We are in the BETA / PRODUCTION-READINESS phase.

We have been converting the system from a "demo/dummy" project into a real,
production-oriented system. The work done so far, in order:

  A) ACCOUNT LIFECYCLE  (real registration + approval)
     - users table now tracks status: PENDING / ACTIVE / REJECTED / SUSPENDED
     - self-service signup (STUDENT / PARENT) creates PENDING accounts
     - admin must approve before the account can log in
     - admin can create accounts directly (immediately ACTIVE)
     - migrations:
        20260902010000_account_lifecycle
        20260902020000_first_login_setup

  B) FIRST-LOGIN OTP SETUP  (real email delivery)
     - admin-created accounts must verify via a short-lived OTP
     - then set their own real password (must_reset_password flag)
     - OTP delivered by real SMTP email via Brevo (nodemailer)
       (OTP_DELIVERY=email); console fallback in dev
     - login UI is a 3-step flow: credentials -> OTP -> set-password
     - "setup" JWTs only unlock the set-password endpoint (no full session)

  C) ADMIN USER MANAGEMENT UI
     - /admin/users with tabs: Approvals, Create Account, Link Parent,
       All Accounts
     - approvals use inline dropdowns (class picker for students,
       student picker to link parents) — no more raw prompt() dialogs
     - admin sidebar navigation (Class Management + User Management)

  D) DEPLOYMENT READINESS + ETHIOPIAN NATIONAL ID (Fayda) + VP-ADMIN
     (newest commit fb5926e)
     - deployment blueprint (render.yaml, backend Dockerfile)
     - Fayda National ID validation (nationalId.js utility)
     - completed vp-administration routes

4. HOW EVERYTHING RUNS (LOCAL)
---------------------------------------------------
Database (only the DB runs in Docker; backend/frontend run natively):
  docker compose up -d db
  # Postgres 15, port 5433, database smart_school, user/pass school/school

Backend (port 5000):
  cd backend
  npm install
  # copy backend/.env.example -> backend/.env and fill real values
  node scripts/applyMigrations.js    # apply migrations
  node scripts/seed.js               # demo users (password: Password123!)
  npm run dev                        # nodemon

Frontend (port 3000):
  cd frontend
  npm install
  npm run dev

URLs:
  Frontend   -> http://localhost:3000
  Backend    -> http://localhost:5000
  Login page -> http://localhost:3000/login

Demo users (password Password123!):
  superadmin@example.com
  principal@example.com
  depthead@example.com
  teacher@example.com
  (and others seeded by scripts/seed.js)
